# Дозапрос №1 по таску 05 — условия ремонта

Источник: основное ревью и атакующее денежное ревью таска 05. Атаки воспроизведены скриптами `e1`–`e6` в
`/private/tmp/claude-501/-Users-azamat-target-ai/d57840e8-91c2-4c42-8abd-2994a912b10d/scratchpad/money-attacks/`.
Каждую атаку — в тест (красный на текущем коде), затем правка. Причины по блокирующим — одной строкой в CONCERNS.

## БЛОКИРУЕТ

1. `saga.py:~499`: `halt_all` между проверкой активации и вызовом Meta → кампания включается после стоп-крана. Условие: флаг `halted` перечитывается из БД непосредственно перед КАЖДЫМ включающим вызовом Meta; если поднят — шаг не выполняется, запуск `awaiting_decision`, всё на паузе.
2. `core.py:~82` + `saga.py:~501`: ошибка Meta при активации → `TypeError` (дублирование `kind` в деталях журнала), запуск висит `in_progress`. Условие: любая ошибка на шаге активации → запуск `awaiting_decision` с кнопками «Повторить/Откатить»; при `outcome_unknown`/`after_execute` Исполнитель сразу ставит на паузу объект, чей статус неизвестен (пауза безвредна), и сверяет статус в Meta.
3. `controls.py:~31`: `halt_all` берёт только кампании со статусом ACTIVE в реестре. Условие: стоп-кран ставит на паузу ВСЕ свои кампании из реестра независимо от записанного статуса (и сверяет реальный статус в Meta), итог — число реально остановленных.
4. `saga.py:~274`: объект Meta с подходящим тегом в имени, которого нет в реестре и который создан не этим запуском, «усыновляется» (группы под чужой кампанией, POST на чужой id). Условие: сверка по тегу усыновляет объект, только если для этого шага в `launch_steps` уже записан ключ идемпотентности (т.е. мы точно отправляли создание) и созданный объект не старше записи шага — иначе это чужой объект: не трогать, запуск `awaiting_decision` с объяснением «в аккаунте есть объект с таким же тегом — создан не системой». Если `find_by_name_tag` не отдаёт время создания — запроси нужное поле тонким адаптером в своей зоне через существующие методы чтения клиента, а если невозможно без правки `meta/` — BLOCKED с точным описанием.
5. `saga.py:~336`: `gather(launch(p1), launch(p2))` одной компании → 2 активные кампании, суммарный `spend_cap` вдвое больше остатка. Условие: запуски одной компании — строго по одному (блокировка на компанию в БД, напр. проверка «нет другого запуска компании в статусе in_progress/awaiting_decision» внутри той же транзакции, что вставляет запуск, плюс asyncio-lock на компанию); второй → «уже идёт запуск, дождитесь».
6. `controls.py:~94`: `resume_company` включает и снятую (`retire_previous`) старую кампанию. Условие: возобновляется только текущая кампания компании (последний успешный запуск); снятые помечаются в реестре как `retired` и никогда не включаются.
7. `controls.py:~171,194`: `set_monthly_limit` вниз → `ApprovalRequired` вылетает исключением ПОСЛЕ сохранения нового лимита, а `spend_cap` в Meta остаётся прежним; остаток лимита снятой кампании съедает резерв; `month_rollover` в autonomous вечно `needs_approval`. Условие: снижение лимита и снижение `spend_cap` — без кнопки и сразу (сначала Meta, потом сохранение: при ошибке Meta лимит не сохраняется и пользователю сообщение); снятая кампания получает `spend_cap` = уже потраченное (с учётом минимума Meta); `month_rollover` в autonomous проходит без кнопки в пределах лимита.

## Что должно заработать

Слепая приёмка прошла бриф, запуская сценарий через приложение, и нашла места, где требование выполнено формально или пользователь видит неправду. Эти места закрываются.

## Критерии приёмки (каждый — тестом через фасад сервиса или фейковый Telegram)

- [ ] **R12:** после выбора страницы бот предлагает кнопками Instagram-аккаунт(ы), связанные со страницей (`get_page_instagram`; в демо — из фейка); ник из текста — подсказка для предвыбора, не замена выбора; если связанного IG нет — объяснение, как привязать.
- [ ] **R09/R11:** «добавь …» (текстом или кнопкой «➕ Компания») во время незаконченной анкеты начинает НОВУЮ анкету с полями из нового сообщения (старая сбрасывается с одной строкой «Прошлая анкета (@bakery_y) отменена»); `/start` тоже сбрасывает незаконченную анкету/вопрос; сайт без схемы (`coffee-x.de`) распознаётся.
- [ ] **R18.1:** любой вопрос-ожидание (ссылка на политику, получатель/плательщик, целевая цена, сумма) имеет кнопку «✖️ Отмена»; если на вопрос пришёл явно другой запрос (команда, кнопка меню, распознанное намерение «отчёт», «компании» и т.п.), вопрос снимается и выполняется запрос, а не отвечается «Это не похоже на ссылку».
- [ ] **R24:** правка плана словами без ключа Claude не выдаёт молча тот же план: офлайн-путь применяет простые правки по ключевым словам (убрать группу по названию/типу — «убери ретаргетинг»; изменить долю бюджета группы — «больше на интересы»), а то, что не понял, честно говорит: «Без ключа Claude понимаю только простые правки: …»; новая версия плана отличается от старой или бот объясняет, почему нет.
- [ ] **R38/R24:** в карточке компании — кнопка «🧭 Новый медиаплан» (и намерение «новый медиаплан для <компания>»): строит новый план с учётом истории компании (в плане строка «Учтено из прошлого: …» из `history`); запуск нового плана снимает старую кампанию по существующим правилам Исполнителя.
- [ ] **R35/R33:** «отчёт за неделю» по запросу отдаёт недельный разбор; в ежедневной сводке «Изменения за сутки» отражают реальные изменения из журнала за эти сутки (тест: после перемотки с перераспределением сводка их показывает).
- [ ] **R40/R41:** карточка компании после исчерпания лимита показывает «Статус: на паузе — лимит месяца исчерпан» (а не «Работает · 495 € из 100 €»), в ответах нет сырых ID объектов Meta; при остановке по исчерпанию лимита приходит одно сообщение «Лимит месяца исчерпан — кампании на паузе до <дата>/до увеличения лимита».
- [ ] **R42:** журнал показывает человекочитаемые действия (без `decision:set_budget`, без `[ta:…]`), пара «начато/завершено» сворачивается в одну строку с итогом.
- [ ] **R43:** если в проверке подключения есть ❌, итог не говорит «в тестовый уровень можно» — вердикт согласован со строками (что блокирует тест, что — боевой).
- [ ] **R69 / нетехнический пользователь:** неверный или отозванный токен бота при старте → русское сообщение «Telegram не принял токен бота — проверьте TELEGRAM_BOT_TOKEN в .env (выдаёт @BotFather)», код выхода ≠ 0, без трассировки; сообщение о сбое задачи планировщика — человеческим названием задачи («ежедневная оптимизация»), не `daily_optimization`.
- [ ] **Тест/боевой без ключа Claude:** до запуска плана бот прямо говорит, что вне демо объявления требуют проверки Контролёра на Claude («добавьте ANTHROPIC_API_KEY в .env»), а не показывает внутреннюю причину `needs_review`.
- [ ] **README:** «остальным — отказ: бот отвечает „Доступ закрыт.“» (как в коде и брифе), вместо «остальным не отвечает»; тест сверки README зелёный.
- [ ] Полный `uv run pytest -q` зелёный; ни одно денежное утверждение не ослаблено; ограждение зелёное; перегенерировать `docs/demo-transcript.md`.

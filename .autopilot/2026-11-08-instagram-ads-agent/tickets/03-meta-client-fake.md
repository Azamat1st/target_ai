## Что должно заработать

Один HTTP-клиент Graph API v27, который говорит с настоящей Meta, а в тестах и в демо — с фейком, подключённым как `httpx.MockTransport`. Фейк повторяет форму настоящих ответов и ошибок, хранит объекты, соблюдает правила Meta, которые проверяют тесты, и умеет «перематывать» дни через симулятор статистики. Ошибки Meta превращаются в типизированную `MetaError` с понятным русским текстом; лимиты запросов — в паузу и повтор.

## Из брифа, дословно

> «Реклама — официальный Meta Marketing API, только плейсменты Instagram. Актуальную версию API и требования к доступам сверь с документацией до кода. Instagram-профили — только через официальный API, скрапить Instagram нельзя.»
> «Ошибки Meta API — понятным русским сообщением в Telegram, без тихих падений; при лимитах запросов — повтор с паузой.»
> «Работа с Meta проверена на фейковом API, который повторяет реальные ответы и ошибки: истёкший токен, нет прав, лимит запросов, отклонённое объявление.»
> «Демо — без Meta: симулятор с правдоподобной статистикой и перемоткой дней»

## Критерии приёмки

- [ ] `MetaClient(token, version, transport=None, validate_only=False, app_secret=None, clock)` реализует протокол `MetaGateway` из спеки (чтение и изменение); токен — заголовком, `appsecret_proof` при наличии секрета; User-Agent дополнен; бюджетные методы принимают только `Money` и проверяют валюту аккаунта
- [ ] `validate_only=True` добавляет `execution_options` (для ads — с `synchronous_ad_review`) ко всем создающим запросам и **не** отправляет `X-Client-Idempotent-Key`; иначе создающие запросы получают ключ, переданный вызывающим
- [ ] Ограничитель на рекламный аккаунт (60 баллов / 300 с, чтение 1, запись 3) + чтение заголовков использования; при кодах лимита — пауза по `estimated_time_to_regain_access`/`reset_time_duration`, иначе экспоненциально, до 5 попыток, затем `MetaError(kind="rate_limit")`; тест на фейке с инъекцией лимита: повтор происходит, время берётся из `Clock` (без реального сна в тестах)
- [ ] Словарь ошибок из §6 → `MetaError(kind, user_message_ru, code, subcode, fbtrace_id, blame_fields)`; тесты на фейке: истёкший токен (190/463), отозванный (190/467), нет прав (200, 10, 294), лимит (17, 80004, 613), неверный параметр (100 с `blame_field_specs`), версия устарела (2635), нет доступа к IG (1815199), бюджет мал (1885272), `is_transient`, 5xx, обрыв соединения
- [ ] `FakeGraphAPI.seed_demo()`: 3 аккаунта (USD/America/New_York, EUR/Europe/Berlin, JPY/Asia/Tokyo) с `currency`, `timezone_name`, `account_status`, `funding_source`, `min_campaign_group_spend_cap`, `/minimum_budgets`; по странице с IG business-аккаунтом и медиа (посты/Reels с лайками, комментариями, insights); каталог ~60 интересов; **чужая активная кампания** в каждом аккаунте
- [ ] Фейк соблюдает правила: создание группы с суженным таргетингом без `advantage_audience` → ошибка; `publisher_platforms` ≠ `["instagram"]` в наших тестах проверяется на стороне клиента/исполнителя, но фейк принимает и запоминает то, что прислали (чтобы тест «только IG» видел реальный запрос); `validate_only` не создаёт объектов и возвращает `{"success": true}`; `spend_cap` ниже минимума → 2446307; включить `DISAPPROVED` объявление → 2490427; повтор с тем же `X-Client-Idempotent-Key` и теми же параметрами → тот же id; списки с `paging`
- [ ] `FakeGraphAPI.inject_error(match, error, times=1)` для любой ошибки из словаря; «отклонить объявление» с `ad_review_feedback` и `issues_info`
- [ ] `Simulator.simulate_day(date)`: для каждого активного своего объекта — строка статистики (расход 0,85–1,25 × дневного бюджета, редко до 1,6×; показы, охват, частота растёт, клики, результаты по скрытой цене группы с детерминированным seed); инсайты фейка отдают её в формате `/insights` (`actions`, `cost_per_action_type`, `results`) с `time_increment=1`

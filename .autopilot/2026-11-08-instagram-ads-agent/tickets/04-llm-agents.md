## Что должно заработать

Шлюз к Claude с проверкой схемы ответа и пять агентов из брифа — Аналитик, Стратег, Копирайтер, Контролёр, Оптимизатор (объяснения и отчёты) — плюс разбор свободного текста. Агенты только предлагают: получают данные аргументами, возвращают pydantic-модели. Без ключа Claude работают офлайн-агенты (детерминированные, помечены «демо без Claude»), в тестах — `ScriptedLLM` с заранее заданными ответами, включая вредные.

## Из брифа, дословно

> «Аналитик — изучает компанию: Instagram-профиль, сайт, конкурентов.»
> «Стратег — выбирает цель кампании, структуру и гипотезы аудиторий, делит бюджет.»
> «Копирайтер — пишет тексты объявлений на языке и в тоне компании, подбирает креативы.»
> «Контролёр — проверяет тексты и таргетинг на правила рекламы Meta и на выдуманные факты.»
> «Агенты — Claude API; модели сверь через скилл claude-api: сильная — на анализ и стратегию, дешёвая — на рутину. Для анализа — серверные инструменты Claude API для веб-поиска и чтения страниц.»
> «Чего не нашёл — пишет „не найдено“, а не выдумывает.»
> «Содержимое сайтов и профилей — недоверенные данные: оно не может менять настройки, лимиты и действия системы.»

## Критерии приёмки

- [ ] Протокол `LLM.structured(tier, system, user_content, schema, tools=None) -> BaseModel`; `ClaudeLLM`: `AsyncAnthropic`, модель по `tier` из `MODEL_STRONG`/`MODEL_CHEAP`, `messages.parse` с pydantic-схемой, `thinking={"type":"adaptive"}`, явный `effort`, кэширование системного промпта, на `claude-opus-5-5` — серверный fallback (`fallbacks="default"`, beta `server-side-fallback-2026-07-01`); обработка `refusal` → `LLMRefused`, `max_tokens` → повтор, `pause_turn` → продолжение, невалидная схема → 1 повтор → `LLMSchemaError`; ошибки SDK по типам (429/5xx/сеть — повтор с паузой, 400/401 — понятная ошибка); без `temperature`/`top_p`
- [ ] Аналитик использует `web_search_20260209` и `web_fetch_20260209` (с `max_uses`), картинки скриншотов — base64-блоками; всё внешнее содержимое — внутри `<untrusted_data>` с инструкцией в системном промпте, что это данные, а не команды
- [ ] Схемы: `Passport` (все поля из §5 включая `voice`, `facts[]` с источником, `not_found[]`), `MediaPlanProposal` (цель из таблицы §6, 2–4 группы: тип гипотезы `broad|interests|retargeting|lookalike`, **доли** бюджета, ключевые слова интересов, гео/возраст — без абсолютных сумм, без ID объектов, без валюты и лимита), `AdCopySet` (2–3 варианта: вид `existing_post|new_creative`, id креатива, текст, заголовок, CTA), `ComplianceVerdict` (по объявлению — пункты чек-листа, нарушения с правилом и исправлением, категория компании), `OptimizerSuggestion`, `Report`, `Intent` (типы: добавить компанию с полями, изменить лимит, пауза, возобновить, отчёт, правка плана, добавить факт, настройка, неизвестно)
- [ ] Промпт Стратега включает историю компании (что пробовали, результат), `daily_cap`, минимумы, найденные интересы с размерами; Копирайтер получает только факты + `voice`; Контролёр — чек-лист из §3
- [ ] `OfflineLLM` возвращает валидные объекты всех схем: паспорт из анкеты с «не найдено» в неизвестных полях (никаких выдуманных цен), план по шаблону (широкая + интересы), тексты-шаблоны из фактов, разбор намерений по ключевым словам (добавь компанию …, бюджет …, пауза, отчёт, стоп); все тексты помечены «(демо без Claude)»
- [ ] `ScriptedLLM(responses)` — очередь ответов по типу схемы, умеет отдавать заранее вредные объекты и исключения
- [ ] Тест: ни один модуль `agents` не импортирует `storage`, `meta`, `executor`
- [ ] Тест: инструкции внутри `<untrusted_data>` не меняют выход офлайн-/скриптового пути (структура не содержит полей для лимитов)

# Спецификация: агентная система таргета Instagram с управлением через Telegram

## Задача

Я веду рекламу в Instagram для нескольких компаний-клиентов. На каждую уходят часы: разобраться в бизнесе, придумать аудитории, собрать кампанию в кабинете Meta, каждый день смотреть статистику и двигать бюджеты. Хочу, чтобы это делала система, а я из Telegram видел, что происходит, и нажимал кнопку там, где решение действительно моё. При этом больше всего боюсь одного: что автоматика потратит чужие деньги сверх оговорённого — из-за ошибки модели, сбоя, двойного нажатия или странного текста на сайте клиента.

## Решение

Telegram-бот на русском, который отвечает только мне. Я добавляю компанию — бот изучает её Instagram, сайт и конкурентов, присылает «паспорт компании», затем короткий медиаплан с кнопками «Запустить / Изменить / Отмена». После «Запустить» кампания собирается в Meta на паузе и включается последним шагом. Дальше бот сам забирает статистику, по правилам перераспределяет бюджет, выключает слабое, предупреждает о выгорании и о проблемах, каждое изменение объясняет одной строкой, присылает ежедневную сводку и недельный разбор. Деньги тратит только код с жёсткими лимитами: месячный лимит компании не может превысить ни один ответ модели, лимит продублирован в самой Meta, стоп-кран останавливает всё одной командой.

Пока нет доступов Meta, всё это проходится в демо-уровне на симуляторе с перемоткой дней. Затем — тестовый уровень (реальное чтение Meta, проверочные запросы на создание) и боевой.

## Словарь

Одно слово — одна вещь; во всём коде, сообщениях бота и README используются только эти термины.

| Термин | Что значит | В коде |
|---|---|---|
| компания | клиент, для которого ведётся реклама | `Company` |
| паспорт | итог анализа компании | `Passport` |
| факт | утверждение о компании с источником; только факты попадают в тексты | `Fact` |
| медиаплан | предложение кампании: цель, группы, бюджеты, объявления | `MediaPlan` |
| группа | группа объявлений (ad set) с одной гипотезой аудитории | `AdGroup` / Meta `adset` |
| объявление | одно объявление (ad) внутри группы | `Ad` |
| креатив | пост/Reels компании или присланное фото/видео | `MediaAsset` |
| цена результата | расход / число целевых результатов (CPA) | `cpa` |
| целевая цена | цена результата от пользователя, иначе оценка Аналитика | `target_cpa` |
| месячный лимит | максимум расхода компании за календарный месяц в часовом поясе рекламного аккаунта | `monthly_limit` |
| режим компании | «С подтверждением» (`confirm`, по умолчанию) или «Автономный» (`autonomous`) | `CompanyMode` |
| уровень работы | `demo` / `test` / `live` — глобально для системы | `Level` |
| подтверждение | одноразовая кнопка на действие; хранится в базе | `Approval` |
| стоп-кран | глобальная остановка всех кампаний системы | `halted` |
| свой объект | кампания/группа/объявление/креатив/аудитория, созданные системой и записанные в реестр | `meta_objects` |
| Исполнитель | единственный код, вызывающий изменяющие методы Meta | `Executor` |

### §2. Модель денег

- `Money(amount_minor: int, currency: str)` — неизменяемый тип; **все** суммы в коде, в базе и в API — только им. Числа с плавающей точкой для денег запрещены; ввод пользователя парсится в `Decimal`.
- `money.offset(currency) -> int` — множитель минимальной единицы Meta по официальной таблице валют (100 для большинства; 1 для валют без дробной части — список в §Meta). Неизвестная валюта → ошибка, не догадка.
- `money.from_major(Decimal, currency) -> Money`, `Money.to_major() -> Decimal`, `money.format_ru(Money) -> "1 234,50 $"` — единственные места пересчёта.
- Клиент Meta принимает только `Money` и сам проверяет, что `money.currency == currency аккаунта`; отправляет `amount_minor` как есть. Целые числа без `Money` в методы бюджета не принимаются (типы + проверка в рантайме).
- Защита от ×100: (1) единственная функция пересчёта; (2) проверка валюты в клиенте; (3) инвариант в `policy`: сумма дневных бюджетов ≤ месячный лимит, сравнение `Money` разных валют — исключение; (4) тесты для USD, KZT, JPY, KRW (последние — без дробной части).

### §3. Политика (лимиты, темп, правила) — чистые функции

Вся логика денег — в модуле `policy`, без ввода-вывода, полностью покрыта тестами.

**Темп (R49).** Месяц и «сегодня» — в часовом поясе рекламного аккаунта.
- `spent_month` — фактический расход всех своих кампаний компании с 1-го числа (из статистики Meta / симулятора).
- `remaining = monthly_limit − spent_month` (не меньше нуля).
- `days_left` = дней до конца месяца, включая сегодня.
- `daily_cap = floor(remaining / days_left)`.
- Поправка на перерасход: Meta в отдельный день может потратить больше дневного бюджета (коэффициент `META_DAILY_OVERSPEND` — §Meta). Если `daily_cap × (1 + overspend) > remaining`, то `daily_cap = floor(remaining / (1 + overspend))`. Так даже худший день не выводит за лимит.
- Если `daily_cap` меньше суммы минимальных бюджетов активных групп — выключаются самые слабые группы; если меньше минимума одной группы — компания ставится на паузу до конца месяца с уведомлением.
- `remaining == 0` → все кампании компании на паузе, уведомление «лимит месяца исчерпан».
- Пересчёт темпа — раз в сутки после закрытия дня аккаунта и при каждом запуске оптимизатора. Снижение — автоматически; рост суммы дневных бюджетов — это «увеличение расхода» (см. ниже).

**Увеличение расхода (R51).** Действие увеличивает расход, если после него сумма дневных бюджетов активных групп компании больше, чем до него. Сюда входят: запуск, возобновление, масштабирование, рост из-за пересчёта темпа, новый месяц, повышение лимита. В режиме `confirm` такое действие возможно только через подтверждение; в `autonomous` — само, но в пределах `daily_cap`.

**Проверка действия.** `check_action(action, snapshot) -> Allowed | Denied(reason) | NeedsApproval(kind)`. Порядок проверок (первая сработавшая решает):
1. стоп-кран включён и действие включает/увеличивает → `Denied`;
2. объект не из реестра своих → `Denied`;
3. уровень `demo`, а компания не демо (и наоборот) → `Denied`;
4. targeting содержит плейсменты кроме Instagram → `Denied`;
5. суммы: валюта ≠ валюте аккаунта, сумма ≤ 0, сумма дневных бюджетов > `daily_cap`, бюджет группы < минимума Meta → `Denied`;
6. изменение бюджета группы > 20% или раньше 24 ч после прошлого (кроме снижения ради лимита и выключения) → `Denied`;
7. увеличение расхода в режиме `confirm` без потреблённого подтверждения → `NeedsApproval`;
8. иначе `Allowed`.

**Валидация медиаплана.** `validate_plan(proposal, company, account, catalog) -> ValidatedPlan`: отбрасывает поля вне схемы; цель — из поддерживаемых; группы: 2–4, у каждой тип гипотезы; интересы — только ID из результатов поиска; бюджеты пересчитываются кодом из `daily_cap` (предложение модели — только доли); группы ниже минимума Meta отбрасываются, пока не уложимся; объявлений 2–3 на группу; каждое объявление прошло Контролёра и детерминированную проверку фактов. Модель не может задать абсолютную сумму, ID объекта Meta, валюту, лимит или режим — таких полей в схеме нет.

**Достаточность данных (R19).** Ретаргетинг — если аудитория вовлечённых в IG-профиль (оценка Meta) ≥ 1 000 человек; похожие — если источник ≥ 1 000 и есть ретаргетинг-аудитория (минимум Meta — §Meta; наш порог выше ради качества, в настройках).

**Узкие и пересекающиеся (R21).** Узкая — оценка Meta < 50 000 (для гео-радиуса ≤ 10 км — < 10 000); настройка. Пересечение: API оценки пересечения нет (§Meta) — эвристика: у двух интерес-групп общих интересов ≥ 50% или одна — подмножество другой → остаётся та, у которой оценка больше. Группы-«холодные» исключают аудиторию ретаргетинга, если она есть.

**Правила оптимизатора (R54–R58).** Значения по умолчанию, хранятся в настройках:

| Параметр | По умолчанию |
|---|---|
| `min_hours_before_decision` | 72 |
| `min_spend_target_cpa_multiple` | 2.0 |
| `budget_change_max_pct` | 20 |
| `budget_change_min_interval_hours` | 24 |
| `kill_cpa_multiple` | 2.0 |
| `strong_cpa_ratio` | 1.0 (цена ≤ целевой) |
| `fatigue_frequency` | 3.0 |
| `weak_ad_cpa_multiple` | 2.0 (к средней по группе) |
| `weak_ad_min_impressions` | 1 000 |

Алгоритм `decide(groups, ads, stats, rules, now) -> list[Decision]` (детерминированный):
1. Группа «созрела», если активна ≥ 72 ч и потратила ≥ 2 × целевая цена.
2. Созревшая группа с ценой ≥ 2 × целевой (или 0 результатов) → выключить (`reason` с цифрами).
3. Объявление в созревшей группе с показами ≥ 1 000 и ценой ≥ 2 × средней по группе (или 0 результатов при расходе ≥ целевой цены) → выключить, если в группе останется ≥ 1 объявление.
4. Освобождённый бюджет и −20% у созревших групп с ценой хуже целевой переносятся на созревшие группы с ценой ≤ целевой, каждой не больше +20% за сутки. Сумма не растёт → автоматически.
5. Если есть сильные группы и `daily_cap` больше текущей суммы → предложение масштабирования (+≤20% каждой сильной, сумма ≤ `daily_cap`); `confirm` → подтверждение, `autonomous` → само.
6. Частота > 3 → предупреждение о выгорании (не действие).
7. Предложения модели-Оптимизатора (если есть ключ) добавляются после, каждое через `check_action`.

**Особые категории (R67).** Контролёр классифицирует компанию; код дополнительно ищет ключевые слова (кредит, ипотека, недвижимость, аренда квартир, вакансия, работа, выборы, партия…). Категория финансов/недвижимости/работы → `special_ad_categories` у кампании, таргетинг без сужения по возрасту/полу, без похожих аудиторий, гео-радиус ≥ минимума Meta (§Meta). Политика → запуск запрещён с объяснением (нужна авторизация рекламодателя в Meta). Я могу поправить категорию через «Изменить».

**Правила Контролёра (R06).** Контролёр (сильная модель) получает чек-лист и возвращает вердикт по каждому пункту; пункты, отмеченные «код», дублируются детерминированной проверкой:
1. Личные характеристики: текст не утверждает и не намекает, что читатель обладает признаком (здоровье, вес, финансы, возраст, религия, ориентация, судимость…) — «Вы страдаете от…», «Устали от долгов?» (код: шаблоны обращения «вы/ты + состояние»).
2. Запрещённый контент: оружие, наркотики, табак и вейпы, взрослый контент, поддельные документы, шпионские средства, мошеннические схемы → объявление не допускается.
3. Ограниченный контент: алкоголь, знакомства, азартные игры, рецептурные препараты, БАДы и похудение, криптовалюты — допускается только с ограничением возраста 18+ (код ставит `age_min=18`) или не допускается (азартные игры).
4. Нереалистичные обещания и «до/после» (похудение, заработок, излечение).
5. Сенсационность и манипуляция: капс больше 30% букв, «!!!», фальшивые элементы интерфейса, ложная срочность без факта (код: доля капса, повтор знаков).
6. Утверждения о цене, скидке, гарантии, сроках, «№1», «лучший» — только если есть в фактах (код: §3 «Проверка фактов»).
7. Особые категории и таргетинг: категория определена верно; таргетинг соответствует ограничениям категории (код: §6).
8. Длина: основной текст ≤ 2 200 символов (лимит IG), рекомендовано ≤ 125 до «ещё»; заголовок ≤ 40 (код).
9. Язык текста совпадает с `voice.language` (код: определение языка по символам).
Нарушение любого пункта → объявление возвращается Копирайтеру с причиной один раз; повторно — выбрасывается из плана с пометкой в плане.

**Проверка фактов (R66).** Детерминированная: из текста объявления извлекаются числа, суммы, проценты, даты и слова-гарантии («гарантия», «бесплатно», «скидка», «лучший», «№1», «100%»); каждое должно встречаться в фактах компании (нормализация пробелов/валют). Не нашлось → объявление возвращается Копирайтеру один раз; снова нет → объявление выбрасывается из плана с пометкой.

### §4. Исполнитель и сага запуска

- `Executor` — единственный модуль, который вызывает изменяющие методы `MetaGateway`. Каждый метод: собрать снимок состояния → `policy.check_action` → запись намерения в журнал → вызов Meta → запись результата в реестр и журнал. Отказ политики — исключение `PolicyDenied` с русским текстом причины.
- **Запуск** (`launch(plan_id, approval_id | None)`):
  1. транзакция: потребить подтверждение (`UPDATE … WHERE status='pending' AND expires_at>now`, ровно одна строка) и вставить строку `launches` с `UNIQUE(plan_id)`; вторая попытка падает на уникальности → «уже запущено»;
  2. перепроверка лимитов на текущих данных (`validate_plan` + `check_action`);
  3. шаги по порядку, каждый — строка `launch_steps` до вызова Meta: `campaign` (PAUSED, со `spend_cap`) → `audience:*` (если нужны) → `adset:N` (PAUSED) → `media:*` (загрузка картинок/видео) → `creative:N:M` → `ad:N:M` (PAUSED) → `activate` (сначала объявления и группы, кампания — последней);
  4. имя каждого объекта Meta содержит тег `[ta:L<launch_id>:<step>]`;
  5. перед созданием шага: если в реестре или в Meta (поиск по тегу в имени) объект шага уже есть — он используется, не создаётся заново;
  6. ошибка на шаге → шаг `failed`, запуск `awaiting_decision`, всё созданное на паузе, сообщение с кнопками «Повторить» / «Откатить».
- **Восстановление (R63).** При старте приложения: запуски в статусе `in_progress`/`awaiting_decision` → сверка реестра с Meta по тегам → всё созданное ставится на паузу (если вдруг активно) → сообщение «Запуск „…“ прервался на шаге N из M. Создано: …» с кнопками «Довести» / «Откатить». «Откатить» удаляет созданные объекты (или архивирует, если удаление невозможно), запуск `rolled_back`.
- **Стоп-кран.** `halt_all()`: флаг `halted=true` в настройках (сначала флаг, потом действия) → пауза всех своих активных кампаний всех компаний (на уровне кампании) → отчёт «остановлено N кампаний». Ошибка Meta на одной кампании не прерывает остальные; неостановленные перечисляются. `resume_system()` (по подтверждению) снимает флаг и ничего не включает; затем по кнопке на каждую компанию — `resume_company`.
- **Пауза компании** — пауза своих кампаний компании; **возобновление** — включение с пересчётом темпа, это увеличение расхода.
- **Лимит в Meta (R50).** Инвариант: у компании **не больше одной активной своей кампании**. Запуск нового плана — шаг саги `retire_previous`: предыдущая кампания ставится на паузу, её `spend_cap` опускается до уже потраченного (минимум Meta соблюдается). `spend_cap` активной кампании = её накопленный расход + `remaining` компании за месяц — значит, Meta не даст потратить больше остатка, даже если бот упал. Пересчитывается при смене лимита и в начале месяца (повышение `spend_cap` = увеличение расхода → правило R51). Единственное исключение — минимум Meta на `spend_cap` (см. §6): если остаток меньше минимума, ставится минимум, разница показывается в плане отдельной строкой и запуск идёт только по кнопке в любом режиме; это ограничение Meta, оно попадает в итоговый отчёт.
- В тестовом уровне все изменяющие вызовы идут с `execution_options=["validate_only"]`; объекты не создаются, в реестр пишется «проверено», запуск получает статус `validated`. Если эндпоинт не поддерживает проверку (§Meta) — создание на паузе и немедленное удаление, с пометкой в журнале.

### §5. Агенты

Каждый агент — функция `async def run(input) -> PydanticModel`, без доступа к базе и к Meta. Общий клиент `llm` делает: вызов Claude со structured output (`messages.parse` с pydantic-моделью), проверку `stop_reason` (`refusal` → ошибка `LLMRefused`, `max_tokens` → повтор с большим лимитом, `pause_turn` → продолжение), повтор 1 раз при невалидной схеме, кэширование неизменной части промпта, на `claude-opus-5-5` — серверный fallback при отказе (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`), адаптивное мышление (`thinking: {type: "adaptive"}`), явный `effort` (high — анализ/стратегия/контроль, low — рутина). Справка по SDK — скилл `claude-api` (`python/claude-api/README.md`, `tool-use.md`).

| Агент | Модель | Вход | Выход (схема) |
|---|---|---|---|
| Аналитик | сильная + `web_search_20260209`, `web_fetch_20260209`, vision | анкета, данные IG API или скриншоты, история | `Passport` |
| Стратег | сильная | паспорт, факты, анкета, `daily_cap`, минимумы Meta, найденные интересы с размерами, история | `MediaPlanProposal` (цель, группы с гипотезами и **долями** бюджета, ключевые слова интересов) |
| Копирайтер | дешёвая | паспорт, факты, гипотеза группы, креативы | `AdCopySet` (2–3 варианта: текст, заголовок, CTA, id креатива) |
| Контролёр | сильная | тексты, таргетинг, факты, категория | `ComplianceVerdict` (по каждому объявлению: ок / нарушение + правило + исправление; категория компании) |
| Оптимизатор | дешёвая | статистика, решения кода | объяснения в одну строку + `OptimizerSuggestion[]` |
| Отчёты (роль Оптимизатора, R33–R35) | сильная (неделя) / дешёвая (день) | статистика, изменения, история | `Report` (текст разделов, выводы, рекомендации) |
| Разбор текста (служебная функция бота, R77) | дешёвая | текст пользователя, контекст диалога | `Intent` (тип + поля) |

Последние две строки — не новые члены команды из брифа, а служебные вызовы модели: отчёты пишет Оптимизатор (он и «следит за статистикой»), разбор свободного текста нужен боту, чтобы «понимать обычный текст».

Офлайн-агенты (`OfflineLLM`) — детерминированные реализации тех же функций без сети: паспорт из анкеты с «не найдено» во всех неизвестных полях, план по шаблону (широкая + интересы из каталога симулятора + до 2 групп по бюджету), тексты-шаблоны из фактов, разбор намерений по ключевым словам. Все их сообщения помечены «(демо без Claude)». В тестах — `ScriptedLLM`: очередь заранее заданных ответов, включая вредные.

Схема `Passport` (поля — ответ на R16): `offer` (что продаёт; цены — только с источником), `audience`, `usp`, `segments[2..4]` (название, боли, мотивы), `competitors[]` (имя, ссылка, чем отличаются), `top_posts[]` (id медиа, почему), `recommended_objective`, `recommended_monthly_budget` (`Decimal` + обоснование, только совет), `expected_cpa` (`Decimal` + обоснование), `risks[]`, `voice` (язык, обращение «ты»/«вы», стиль, характерные фразы — из постов и сайта), `facts[]` (текст, источник), `not_found[]`. Пустое → «не найдено».

### §6. Meta Marketing API

Факты о версии, разрешениях, эндпоинтах, ошибках — в `research-meta.md` (сверено с документацией 2026-11-08; ссылки там). Этот раздел — решения, которые из них следуют. Исполнители читают `research-meta.md` по номерам разделов, указанным в скобках.

**Версия и транспорт.** `META_API_VERSION=v27.0` по умолчанию (v24 перестаёт работать 10.11.2026, v25 — 23.02.2027) (р.1). Базовый URL `https://graph.facebook.com/{version}/`. Токен — заголовком `Authorization: Bearer`, плюс `appsecret_proof` (HMAC-SHA256 токена ключом `META_APP_SECRET`), если секрет задан. User-Agent дополняется строкой `TargetAI/<версия> (<MODEL_STRONG>) httpx` — Meta просит агентов себя обозначать (р.«Вывод» 13). Заголовок `X-Ad-Api-Version-Warning` пишется в лог, ошибка 2635 → уведомление «версия API устарела, обновите META_API_VERSION».

**Нужные разрешения** (р.2): `ads_management`, `ads_read`, `pages_show_list`, `pages_read_engagement`, `pages_manage_ads`, `pages_read_user_content`, `instagram_basic`, `instagram_manage_insights`; `business_management` — желательно. Для своих (расшаренных в своё бизнес-портфолио) рекламных аккаунтов хватает Standard-доступа без App Review (р.3). Токен — системного пользователя (бессрочный или 60-дневный). Для создания рекламы в Direct и лид-форм нужен токен Страницы: `GET /{page_id}?fields=access_token` от имени системного пользователя с задачей ADVERTISE на Странице.

**Лимиты запросов** (р.3, р.18). Limited-доступ (по умолчанию): 60 баллов за 5 минут на рекламный аккаунт, чтение = 1, запись = 3, блокировка 300 с. Поэтому в клиенте — ограничитель на каждый аккаунт (корзина баллов) + чтение заголовков `X-Business-Use-Case-Usage` / `X-Ad-Account-Usage` / `X-FB-Ads-Insights-Throttle`: при ≥ 90% — пауза до сброса. Коды 4, 17, 32, 613, 80000–80014 → ждать `estimated_time_to_regain_access` (мин) или `reset_time_duration` (с), иначе экспоненциально 30 с × 2ⁿ, до 5 попыток, во время блокировки запросов не слать; затем `MetaError(kind=rate_limit)` с русским текстом. Правка одного объекта — не чаще раза в 30 с. Запуск на Limited-доступе занимает несколько минут — бот так и пишет.

**Цели** (р.4). Поддерживаемые цели и их настройка:

| Цель (в боте) | objective | optimization_goal | billing_event | destination_type | promoted_object | CTA креатива | Результат в статистике |
|---|---|---|---|---|---|---|---|
| Сообщения в Direct | `OUTCOME_ENGAGEMENT` | `CONVERSATIONS` | `IMPRESSIONS` | `INSTAGRAM_DIRECT` | `page_id` | `INSTAGRAM_MESSAGE` (`app_destination: INSTAGRAM_DIRECT`) | `onsite_conversion.messaging_conversation_started_7d` |
| Лид-форма | `OUTCOME_LEADS` | `LEAD_GENERATION` | `IMPRESSIONS` | `ON_AD` | `page_id` | `SIGN_UP` + `lead_gen_form_id` | `onsite_conversion.lead_grouped`, иначе `lead` |
| Трафик на сайт | `OUTCOME_TRAFFIC` | `LINK_CLICKS` | `IMPRESSIONS` | `WEBSITE` | — | `LEARN_MORE` + ссылка | `link_click` |
| Трафик в профиль | `OUTCOME_TRAFFIC` | `PROFILE_VISIT` | `IMPRESSIONS` | `INSTAGRAM_PROFILE` | `page_id` | `VIEW_INSTAGRAM_PROFILE` | `results` / `cost_per_result` |
| Охват | `OUTCOME_AWARENESS` | `REACH` | `IMPRESSIONS` | — | `page_id` | — | `reach`; «цена результата» = цена 1 000 охвата |

- Трафик в профиль через API доступен не всем аккаунтам (limited availability): перед предложением этой цели — проверочный запрос; если недоступно — цель «Трафик на сайт» со ссылкой на профиль `https://instagram.com/<ник>` и строкой в плане об этом. Особые категории для неё не поддерживаются.
- Лид-форма создаётся `POST /{page_id}/leadgen_forms` токеном Страницы: имя, вопросы (имя, телефон по умолчанию), `privacy_policy {url, link_text}` — ссылку даёт пользователь (R18.1).
- Во всех кампаниях `special_ad_categories` передаётся явно (`[]` или категория + `special_ad_category_country`).

**Только Instagram** (р.5). В каждой группе: `targeting.publisher_platforms=["instagram"]`, `device_platforms=["mobile"]`, явный `instagram_positions` по цели: сообщения и лиды — `["stream","story"]`; трафик, профиль, охват — `["stream","story","reels"]`. Поле `placement_soft_opt_out` не передаётся никогда. `advantage_state=DISABLED` у такой кампании — норма. Исполнитель отклоняет любой targeting без этих полей или с другими платформами.

**Advantage+ audience** (р.6): `targeting.targeting_automation.advantage_audience` передаётся всегда явно: `1` — широкая группа, `0` — интересы, ретаргетинг, похожие. При `1` возраст — только подсказка (`age_min` 18–25).

**Креативы** (р.13). `degrees_of_freedom_spec.creative_features_spec.standard_enhancements.enroll_status = "OPT_OUT"` в каждом креативе — чтобы Meta не переписывала тексты (иначе появятся утверждения, которых нет в фактах) и не было ошибки 3858082.
- Существующий пост/Reels: `object_id=<page_id>`, `instagram_user_id`, `source_instagram_media_id` (+ CTA по цели). Подпись — подпись поста, тексты Копирайтера к нему не применяются; перед использованием — проверка `boost_eligibility_info`. Поля `instagram_actor_id`, `instagram_story_id` не использовать (устарели).
- Свой креатив: `object_story_spec` с `page_id`, `instagram_user_id` и `photo_data` (`image_hash` из `POST /act_{id}/adimages`) или `video_data` (`video_id` из `POST /act_{id}/advideos` + превью). Файлы из Telegram скачиваются в `data/media/` (лимит Bot API на скачивание — 20 МБ; больше — бот просит прислать файл поменьше).

**Интересы и аудитории** (р.7–9).
- Поиск: `GET /search?type=adinterest&q=<слово>` → `id, name, path`; размер — через оценку аудитории группы. Только ID из ответа поиска попадают в таргетинг.
- Оценка: `GET /act_{id}/delivery_estimate` (`targeting_spec`, `optimization_goal`, `promoted_object`) → `estimate_mau_lower_bound/upper_bound`; запасной вариант — `/reachestimate` (`users_lower_bound/upper_bound`). Значение `-1` = «неизвестно», не «пусто».
- Пересечение аудиторий через API недоступно — эвристика из §3.
- Ретаргетинг: `POST /act_{id}/customaudiences` с `prefill=1` и правилом `event_sources: [{id: <ig_user_id>, type: "ig_business"}]`, событие `ig_business_profile_all`, давность 365 дней. Ошибки 200/1870034, 1870090, 1870092 → «Примите условия пользовательских аудиторий в Ads Manager» со ссылкой.
- Похожие: `subtype=LOOKALIKE`, `origin_audience_id`, `lookalike_spec={"type":"similarity"}`; без `country` (в v27 отклоняется), гео берётся из группы. Наполняется 1–6 ч — группа похожих создаётся в запуске, но в плане помечено «заполняется». Для особых категорий похожие недоступны.

**Минимумы и лимиты расходов** (р.10).
- Минимальные дневные бюджеты — `GET /act_{id}/minimum_budgets` → `min_daily_budget_imp` (охват), `min_daily_budget_high_freq` (клики, визиты, сообщения, лиды), `min_daily_budget_low_freq`. Кэш на сутки на аккаунт.
- `META_DAILY_OVERSPEND = 0.75` (по умолчанию, в настройках): справка Meta допускает до +75% в отдельный день при недельном потолке 7× дневного бюджета; документация для разработчиков пишет 25% — берём консервативное значение.
- Снижение дневного бюджета группы — не ниже уже потраченного сегодня + 10% (правило Meta); ниже — пауза группы.
- Изменение бюджета группы — не больше 4 раз в час (у нас и так раз в сутки).
- `spend_cap` кампании — в минимальных единицах, минимум — поле аккаунта `min_campaign_group_spend_cap` (≈ $100). Значение = накопленный расход кампании + остаток месячного лимита компании. Если это меньше минимума Meta, ставится минимум, а в плане отдельной строкой: «Защитный лимит в Meta — 100,00 $ (меньше Meta не позволяет), остаток вашего лимита — 80,00 $; разницу контролирует бот». В «Автономном» режиме такой запуск всё равно требует кнопки. `spend_cap` аккаунта система не трогает: он задел бы чужие кампании, и в документации противоречие по единицам записи.

**Деньги** (р.11). Минимальные единицы по таблице валют Meta: множитель 1 у CLP, COP, CRC, HUF, ISK, IDR, JPY, KRW, PYG, TWD, VND; у остальных поддерживаемых — 100. Валюты, которых нет в таблице (например, KZT, UZS — Meta их не поддерживает), → ошибка. Если пользователь пишет бюджет в другой валюте, чем аккаунт, бот не пересчитывает по курсу, а просит сумму в валюте аккаунта.

**Состояние аккаунта** (р.11). `account_status`: 1 — активен; 2 — отключён («аккаунт ограничен»); 3, 8, 9 — «проблема с оплатой»; 7 — «на проверке рисков»; 100, 101 — закрывается/закрыт. Пустой `funding_source` → «нет способа оплаты, объявления не будут показываться». `disable_reason` переводится словарём.

**Проверочные запросы** (р.12). `execution_options=["validate_only"]` — на `campaigns`, `adsets`, `adcreatives`; на `ads` — `["validate_only","synchronous_ad_review"]`. Успех — `{"success": true}`; провал — ошибка с `error_data.blame_field_specs`. Ключ идемпотентности с проверочными запросами не отправляется. Если для проверки дочернего объекта нужен существующий родитель (группе — кампания, объявлению — группа), тестовый уровень создаёт родителя **на паузе** с пометкой «[ТЕСТ]» в имени, проверяет дочерние, затем удаляет созданное. Включение в тестовом уровне запрещено политикой.

**Без дублей** (р.20). Для каждого создающего шага саги UUID генерируется и **сохраняется в `launch_steps` до вызова**, затем уходит в заголовке `X-Client-Idempotent-Key` (действует 7 дней в пределах аккаунта). Заголовок может молча игнорироваться (функция раскатывается), поэтому второй рубеж — тег `[ta:L<id>:<шаг>]` в имени объекта и сверка перед созданием: дочерние объекты — через списки `/{campaign_id}/adsets`, `/{adset_id}/ads`; кампании и креативы — через `/act_{id}/campaigns`, `/act_{id}/adcreatives` с отбором по тегу в коде (фильтр по имени на стороне API не подтверждён).

**Модерация** (р.14). Вебхуки требуют публичного HTTPS — не используются; опрос `GET /{ad_id}?fields=effective_status,ad_review_feedback,issues_info` каждые 30 мин, пока есть объявления в `PENDING_REVIEW`/`IN_PROCESS`, и раз в 3 ч для остальных. `DISAPPROVED` → причина из `ad_review_feedback.global` / `placement_specific.instagram` и `issues_info`. Отклонённое объявление включить нельзя (2490427, 2490468) — исправление создаётся **новым объявлением** в той же группе, старое удаляется.

**Статистика** (р.15). `GET /{object}/insights` с `level=adset|ad`, `time_increment=1`, `time_range` (даты аккаунта), `use_unified_attribution_setting=true`, поля `spend, impressions, reach, frequency, clicks, inline_link_clicks, ctr, actions, cost_per_action_type, results, cost_per_result`. Не чаще раза в 15 мин (у нас — раз в 3 ч). Данные за последние 3 дня перезапрашиваются (Meta дообновляет).

**Instagram** (р.16). Профиль: `GET /{ig_user_id}?fields=username,name,biography,website,followers_count,media_count`; медиа: `GET /{ig_user_id}/media?fields=id,caption,like_count,comments_count,media_type,media_product_type,permalink,timestamp,media_url,thumbnail_url,boost_eligibility_info&limit=50`; статистика медиа: `GET /{media_id}/insights?metric=reach,saved,shares,total_interactions,views` (по возможности; ошибка по одной метрике не роняет анализ). Конкуренты: `business_discovery.username(<ник>){followers_count,media_count,biography,website,media{caption,like_count,comments_count,media_type,permalink,timestamp}}` — только бизнес-/авторские аккаунты.

**Особые категории** (р.17). Enum: `FINANCIAL_PRODUCTS_SERVICES`, `HOUSING`, `EMPLOYMENT`, `ISSUES_ELECTIONS_POLITICS`, `ONLINE_GAMBLING_AND_GAMING`. Для финансов/жилья/работы: возраст 18–65+, без выбора пола, радиус ≥ 15 км (≥ 25 км для США/Канады), без исключения локаций и почтовых индексов, без поведений/демографии, без похожих аудиторий, `special_ad_category_country` обязателен. Политика и азартные игры → запуск запрещён с объяснением (нужна отдельная авторизация Meta). Если гео включает страны ЕС — у группы нужны `dsa_beneficiary` и `dsa_payor`: бот спрашивает у пользователя, кто получатель и плательщик рекламы (это факт о клиенте).

**Токен** (р.19). `GET /debug_token?input_token=<токен>&access_token=<META_APP_ID>|<META_APP_SECRET>` → `is_valid`, `expires_at` (0 — бессрочный), `data_access_expires_at`, `scopes`. Без `META_APP_ID`/`META_APP_SECRET` — проверка через `GET /me` (действителен ли), срок неизвестен — бот так и говорит. Meta не уведомляет об истечении — проверка раз в сутки.

### §7. Фейковый Graph API и симулятор

- `FakeGraphAPI` — `httpx.MockTransport`-обработчик, повторяющий форму реальных ответов (`{"id": ...}`, `{"data": [...], "paging": {...}}`, `{"success": true}`) и ошибок (`{"error": {"message", "type", "code", "error_subcode", "error_user_title", "error_user_msg", "fbtrace_id"}}`), с хранилищем объектов в памяти (или в SQLite для демо, чтобы переживать перезапуск).
- Предзаполнение: 3 демо-аккаунта (USD / America/New_York, EUR / Europe/Berlin, JPY / Asia/Tokyo — последний без дробной части, чтобы демо показывало пересчёт), по странице и IG-аккаунту, каталог интересов (~60 штук с размерами), минимальные бюджеты, **чужая активная кампания** в каждом аккаунте. Фейк соблюдает правила из §6, которые проверяют тесты: валидация `publisher_platforms`, `advantage_audience` обязателен при суженном таргетинге, `validate_only` не создаёт объектов, минимальный `spend_cap`, корзина баллов лимита запросов (включаемая), отклонённое объявление нельзя включить.
- Инъекция ошибок для тестов: истёкший токен (190/463), нет прав (200/10), лимит запросов (17, 80004 + заголовок `X-Business-Use-Case-Usage`), невалидный параметр (100), отклонённое объявление (`effective_status=DISAPPROVED` + причина), временная ошибка (`is_transient`), обрыв соединения.
- `Simulator` — генератор статистики поверх тех же объектов: у каждой группы скрытая «истинная» цена результата (детерминированный seed от id), дневной расход 0,85–1,25 × бюджета (изредка до 1,6×, но не выше правила Meta), частота растёт со временем, CTR объявлений различается. Перемотка дня генерирует строку статистики на каждый активный объект.
- `SimClock` — симулированное «сейчас», хранится в базе; в демо все модули берут время только из `Clock`.

4. Что требует проверки бизнеса или App Review и сколько это обычно занимает (сроки — типичные, не гарантированные):
   - для своих рекламных аккаунтов (свои и клиентские, расшаренные в ваше бизнес-портфолио; приложением пользуетесь только вы) App Review **не нужен**: хватает Standard-доступа к `ads_read`/`ads_management`, который выдаётся сразу; проверка бизнеса (Business Verification) тоже не нужна;

   - Advanced-доступ к разрешениям (если когда-нибудь понадобятся чужие аккаунты, не расшаренные вам) — App Review по каждому разрешению плюс Business Verification; App Review обычно 3–7 рабочих дней, Business Verification — несколько рабочих дней;
   - токен системного пользователя — сразу; бессрочный или 60-дневный.
5. Переход демо → тест → боевой: что проверить, какие команды, что увидеть.

| `executor` | все изменения в Meta | `Executor(db, gateway_factory, policy, clock, notifier)`: `launch(plan_id, approval_id)`, `recover_incomplete()`, `halt_all()`, `resume_system(approval_id)`, `pause_company(id)`, `resume_company(id, approval_id)`, `apply_decisions(company_id, decisions, approval_id=None)`, `apply_creative_fix(ad_id, copy, approval_id)`, `set_monthly_limit(company_id, Money, approval_id)`, `month_rollover(company_id, approval_id)`, `rollback_launch(launch_id)` | сага, реестр, журнал |
| `services` | сценарии | `Onboarding`, `Analysis`, `Planning`, `Optimization`, `Reporting`, `Alerts`, `Moderation`, `ConnectionCheck`, `LevelSwitch`, `DemoTime` — их вызывает бот и планировщик | оркестрация агентов, политики, Исполнителя |
| `scheduler` | расписание | `Scheduler(db, clock, services).tick()`, `run_until(datetime)` (для перемотки) | таблица jobs |
| `notify` | исходящие сообщения | `Notifier` (протокол `send(chat_id|None, text, buttons)->message_id`, `edit`), `TelegramNotifier(bot)` | форматирование, разбиение |
| `bot` | Telegram | `build_dispatcher(app)->Dispatcher` | роутеры, клавиатуры, FSM анкеты |
| `app` | сборка | `App.create(settings, overrides)`, `App.run()`; `python -m target_ai` | связывание зависимостей |

**Швы для тестов** (поведение проверяется только через них):
1. **Главный шов — приложение целиком:** `App.create(settings, overrides={llm: ScriptedLLM|OfflineLLM, meta_transport: FakeGraphAPI.transport, clock: SimClock, bot_session: FakeTelegramSession})` + подача апдейтов `dp.feed_update`. Сквозной тест, денежные тесты (двойное нажатие, сбой, чужой ID, стоп-кран, чужие кампании) — здесь.
2. **Чистые функции `policy` и `money`** — табличные тесты лимитов, темпа, правил, валют, вредных ответов модели.
3. **`MetaClient` на `FakeGraphAPI`** — ошибки Meta и повторы.

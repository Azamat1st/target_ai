## Что должно заработать

Жизнь кампании после запуска. Планировщик по таблице `jobs` (с реальными и симулированными часами) забирает статистику, раз в сутки пересчитывает темп и запускает оптимизатор (`policy.decide` + предложения модели → `Executor.apply_decisions`), каждые 15 минут проверяет модерацию и тревожные сигналы, присылает ежедневную сводку и недельный разбор. В демо «⏩ +N дней» прогоняет симулятор и все задачи день за днём и присылает одно итоговое сообщение.

## Из брифа, дословно

> «Оптимизация по расписанию: бот забирает статистику, перераспределяет бюджет между группами, выключает слабые объявления и группы, масштабирует сильные, предупреждает о выгорании креативов. Каждое изменение — с объяснением в одну строку.»
> «Отчёты в Telegram: ежедневная сводка в заданное время, недельный разбор с выводами и рекомендациями, отчёт по запросу.»
> «Бот следит за модерацией и сообщает об отклонённых объявлениях с причиной и вариантом исправления.»
> «Мгновенные уведомления: объявление отклонено, группа не получает показов, аккаунт ограничен, проблема с оплатой, токен скоро истечёт или истёк, резкий рост расхода или цены результата.»
> «Демо — без Meta: симулятор с правдоподобной статистикой и перемоткой дней»

## Критерии приёмки

- [ ] `Scheduler.tick()` выполняет просроченные задачи из `jobs` по `Clock`, задачи переживают перезапуск; `run_until(dt)` для перемотки; ошибка одной задачи не останавливает остальные и уходит уведомлением
- [ ] Статистика: забор по группам и объявлениям (`time_increment=1`, последние 3 дня перезапрашиваются) → `stats_daily`; «результат» — по `action_type` цели (§6); `spent_month` — по датам часового пояса аккаунта
- [ ] Оптимизация раз в сутки: темп → `policy.decide` → (если есть ключ) предложения модели-Оптимизатора → `Executor.apply_decisions`; автоматическое (перераспределение без роста, выключение слабых) применяется в обоих режимах; рост расхода в `confirm` → сообщение с кнопкой; в `autonomous` — само в пределах лимита; каждое изменение — строка с цифрами
- [ ] Новый месяц: пересчёт по новому лимиту и повышение `spend_cap` — как увеличение расхода (кнопка в `confirm`)
- [ ] Модерация каждые 15 мин: `DISAPPROVED` → уведомление с причиной + исправление от Копирайтера, проверенное Контролёром → «Применить исправление» (`confirm`) / само (`autonomous`)
- [ ] Уведомления каждые 15 мин: нет показов ≥ 6 ч; `account_status` ≠ 1 и пустой `funding_source` (ограничен / оплата); токен (раз в 6 ч и при ошибке 190): истекает ≤ 7 дней / истёк; расход дня > 1,5× дневного бюджета; цена дня > 2× средней за 7 дней; не больше одного уведомления на ключ события в сутки (`alerts_sent`); пороги — из настроек
- [ ] Отчёты: ежедневная сводка в заданное время (по каждой компании: вчера, с начала месяца из лимита, результаты, цена против целевой, изменения, предупреждения); недельный разбор по понедельникам (сильная модель; выводы → `history`); отчёт по запросу по одной компании или всем; офлайн — шаблонный текст из цифр
- [ ] История компании: по каждой группе/объявлению итог (гипотеза, аудитория, креатив, дни, расход, результаты, цена, вердикт) пишется при выключении и в недельном разборе
- [ ] `DemoTime.advance(days)`: по дням — симулятор → статистика → задачи; ежедневные сводки свёрнуты в одно итоговое сообщение (по дню строка) + список изменений оптимизатора с объяснениями + недельный разбор, если прошёл понедельник; тест: запуск → +7 дней → есть хотя бы одно перераспределение бюджета по правилам с объяснением

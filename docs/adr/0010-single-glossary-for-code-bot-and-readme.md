## Контекст

Система описывается тремя языками сразу: терминами Meta (ad set, ad, CPA), терминами кода и русскими сообщениями бота для нетехнического человека. Одно и то же легко называть по-разному, особенно там, где речь о деньгах.

## Решение

Принят единый словарь, в котором одно слово означает одну вещь, и используется он во всём коде, сообщениях бота и README. Основные термины: компания (`Company`), паспорт (`Passport`), факт (`Fact`), медиаплан (`MediaPlan`), группа (`AdGroup`, в Meta `adset`), объявление (`Ad`), креатив (`MediaAsset`), цена результата (`cpa`), целевая цена (`target_cpa`), месячный лимит (`monthly_limit`), режим компании (`CompanyMode`), уровень работы (`Level`), подтверждение (`Approval`), стоп-кран (`halted`), свой объект (`meta_objects`), Исполнитель (`Executor`). Слово из словаря не используется ни в каком другом смысле.

## Почему

- Свободные синонимы («бюджет» вместо «лимит», «аккаунт» вместо «компания», «подтвердить» вместо «Approval») отвергнуты: в этой системе путаница в слове «бюджет» (месячный лимит, дневной бюджет группы, бюджет в анкете) приводит к денежной ошибке. «Месячный лимит» и «дневной бюджет группы» должны быть разными словами.
- Использование терминов Meta в интерфейсе («ad set», «CPA») отвергнуто: бот отвечает нетехническому человеку по-русски. Термины Meta остаются только на границе с API.
- Отдельные словари для кода и для бота отвергнуты: перевод между ними становится ещё одним местом, где смысл теряется.

## Последствия

- Слова «компания» (клиент, а не рекламный аккаунт) и «группа» (ad set, а не группа людей) требуют постоянной дисциплины; нарушение в сообщении бота или в README придётся исправлять как дефект.
- Пользователь, читающий документацию Meta, увидит другие слова, и соответствие «группа = ad set» придётся пояснять в README.
- Новый термин нельзя вводить мимоходом: он добавляется в словарь, иначе словарь перестаёт быть единственным источником.

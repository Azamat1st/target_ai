## Контекст

Доступов Meta пока нет, а демо должно проходить весь цикл без них. Тесты денег должны проверять сбои Meta (истёкший токен, лимит запросов, отклонённое объявление, обрыв соединения), которые на живом аккаунте не воспроизвести по заказу.

## Решение

С Meta разговаривает один HTTP-клиент на `httpx` без `facebook-business` SDK. Его транспорт подменяется. В тестах и в демо подключён `FakeGraphAPI` — обработчик `httpx.MockTransport` с хранилищем объектов, повторяющий форму реальных ответов и ошибок. Тот же код клиента работает в тестах, в демо и в бою, меняется только транспорт. Демо-симулятор статистики лежит поверх тех же объектов. Фейк соблюдает правила Meta, которые проверяют тесты: валидация плейсментов, обязательный `advantage_audience`, `validate_only` ничего не создаёт, минимальный `spend_cap`, отклонённое объявление нельзя включить, корзина баллов лимита запросов.

Единый фейк для тестов и демо принят за пользователя в режиме полного автомата.

## Почему

- `facebook-business` SDK отвергнут: у него нет такого удобного шва для подмены транспорта, а нам нужен один код, одинаково работающий на фейке и на Meta.
- Мокирование на уровне методов клиента отвергнуто: оно не проверяет сериализацию запросов, разбор ошибок по `code`/`error_subcode`, повторы и ограничитель запросов, то есть ровно те места, где живут ошибки.
- Отдельный симулятор для демо и отдельный фейк для тестов отвергнуты: они разошлись бы, и демо показывало бы поведение, которого нет в тестах. Один фейк означает, что демо-цикл доказывает то же, что и тесты.

## Последствия

- Зелёные тесты доказывают, что клиент согласован с нашим представлением о Meta, а не с самой Meta. Фейк может отстать от реальных ответов; это нужно сверять при каждой смене версии API и после первого реального прогона.
- Фейк нужно поддерживать как продукт: правила Meta, которые он воспроизводит, закреплены в спецификации и в `research-meta.md`.
- Статистика в демо синтетическая (скрытая «истинная» цена результата на группу), поэтому красивое поведение оптимизатора в демо ничего не говорит о качестве реальных решений.
- Демо-состояние может храниться в SQLite, чтобы переживать перезапуск: это ещё одна таблица, которую надо мигрировать.
